**Cross-cutting** — applies to every service, script, manifest, and template that addresses a peer.

## The rule

An **external host** (a VM or machine outside the compose/Kubernetes network) is addressed by a reserved, environment-stable name in the `*.internal` namespace. A **peer inside** the cluster is addressed by the platform's own DNS name (a Service name: `django`, `postgres`).

Addresses are never written into committed code, config, templates, or scripts. The single home for a `name -> address` mapping is `secrets/<env>/`, encrypted with sops. See [Configuration Conventions](./tech-stack/configuration.mdx) for env-file layout and placeholder notation.

## Naming scheme

| Form                   | Meaning                                                                    | Examples                                                |
| ---------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------- |
| `<role>.internal`      | the endpoint a service talks to; singular per environment                  | `db.internal`, `gateway.internal`, `dns.internal`       |
| `<role>-<n>.internal`  | one member of an **ordered set** (`<n>` is a 1-based index)                | `proxmox-1.internal`, `k8s-worker-3.internal`           |
| `<role>-node.internal` | the **node** that carries a service, where the node also has a member name | `db-node.internal` — the Proxmox node holding the DB VM |

`<role>` is the service or infrastructure role in `lower-kebab-case`.

Distinguish the **endpoint** from the **machine that runs it**: `db.internal` is the database VM; `db-node.internal` is the Proxmox node that hosts that VM.

An index is an ordering handle, **not an address**. `k8s-worker-1.internal` and `proxmox-1.internal` pair positionally with each other; neither implies anything about the last octet of its address.

## Fields: canonical name and aliases

A hosts-format line is `<address> <name> [<alias>...]`.

- **Field 1** is the address.
- **Field 2 is the canonical name** — the name every lookup is expected to work with, and the only field an ordered list is keyed on.
- **Fields 3+ are aliases** of the same host, written _on the same line_.

```text
xxx.xxx.xxx.xxx proxmox-1.internal
xxx.xxx.xxx.xxx proxmox-2.internal
xxx.xxx.xxx.xxx proxmox-3.internal db-node.internal
```

Aliases go on the same line **on purpose**. A separate line repeating the address would be a second copy of a fact that must agree with the first, with nothing to detect divergence. On one line the names are one fact, so they cannot drift, and the file gains no extra line for a positional consumer to trip over.

## Where names live

| File                                                 | Contents                                                                                            | Resolvable on the dev machine / in-cluster? |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `secrets/<env>/hosts.sops.yaml`                      | single hosts — `db.internal`, `gateway.internal`, `dns.internal`                                    | **yes**                                     |
| `secrets/<env>/proxmox-hosts.sops`                   | ordered `proxmox-N.internal` members, with `db-node.internal` as an alias on the line it belongs to | no                                          |
| `secrets/<env>/k8s-workers-hosts.sops`               | ordered `k8s-worker-N.internal` members                                                             | no                                          |
| `ansible/inventory/<env>/group_vars/files.sops.yaml` | `wywy_pod_cidr`                                                                                     | n/a                                         |

`hosts.sops.yaml` is consumed **whole** by the two resolvers (`resolve-hosts.sh` overlays it into the operator's `/etc/hosts`; the `k8s_network` Ansible role renders it into the cluster's CoreDNS hosts block), so anything added to it becomes resolvable on the dev machine and inside the cluster. Infrastructure addresses — Proxmox nodes, the gateway — deliberately do **not** belong there.

## File format

- hosts-format: `<address> <name> [<alias>...]`, one **host** per line, whitespace-separated.
- Non-YAML hosts-format secrets use the **`.sops`** extension. `.sops.yaml` is for YAML content governed by an `encrypted_regex` rule; routing hosts-format content through it leaves the key unencrypted.

## Resolution

**Name → address** is the `wywy_hosts` lookup plugin, so no caller re-implements the predicate and each outcome is a defined contract:

```jinja
lookup('wywy_hosts', '<file>', '<name>')
```

The plugin resolves `<file>` under `secrets/<env>/` and decrypts it with `sops`. It is the single implementation used by inventory, playbooks, and tests.

| Outcome                           | Result                                                       |
| --------------------------------- | ------------------------------------------------------------ |
| exactly one line carries the name | the address is returned                                      |
| no line carries it                | `AnsibleError` containing `no entry for '<name>'`            |
| two or more lines carry it        | `AnsibleError` containing `ambiguous` and each claiming line |
| file missing/unreadable           | `AnsibleError` carrying sops's own message                   |

A file the decryptor cannot read — absent, unreadable, undecryptable, wrong key — fails before any lookup, with **sops's own message**. The plugin does not pre-check existence; sops reports those conditions more precisely than a length-and-existence check could, and the check would be a second, weaker copy of the same rule.

Two properties are deliberate:

- **Failure is an exception, never a value.** A resolver that returns `no-entry-<name>` hands a caller something that looks like an answer; the caller then tries to reach a machine by that name and the real problem is three layers away.
- **An ambiguous name is an error, not a first match.** Two lines claiming one name means the file disagrees with itself about which machine holds that name. Taking the first match would silently address the wrong host — a failure that surfaces much later as an inexplicable connection instead of here as a file problem.

A name repeated _within one line_ is not ambiguous: same line, same address.

**Ordered role list** — field 2 only, which is what keeps an alias out of the member list:

```jinja
query('wywy_hosts', '<file>', prefix='<prefix>')
```

Both operations require field 1 to be a valid IP address, so a comment line's `#` is never read as an address. Matching is whitespace-agnostic (spaces or tabs), and a `.` inside a name is literal rather than a regex wildcard.

**Never read `config/.env.network`.** It is deprecated and no new code may take an address from it; the remaining topology keys there are scheduled for deletion.

## Consumers

| Consumer                                                   | Reads                                                 | Predicate                                               |
| ---------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------- |
| `ansible/plugins/lookup/wywy_hosts.py`                     | whatever sops file it is given under `secrets/<env>/` | any name field → address; raises on absent or ambiguous |
| `scripts/lib/hosts.sh` (`hosts_ip`, `hosts_ip_real`)       | `hosts.sops.yaml`                                     | field 2                                                 |
| `scripts/lib/resolve-hosts.sh`                             | `hosts.sops.yaml`                                     | whole file (by design)                                  |
| `ansible/roles/k8s_network` (`playbooks/k8s/coredns.yaml`) | `hosts.sops.yaml`                                     | whole file (by design)                                  |
| Ansible inventory — `inventory/<env>/group_vars/*.yaml`    | `wywy_hosts` lookup; name = `inventory_hostname`      | any name field                                          |
| `scripts/proxmox/target-loop.sh`                           | ordered lists                                         | field 2                                                 |

## Deviations in the current tree

These are known gaps between this convention and the repository, not alternative conventions:

- `secrets/prod/` does not exist — only dev resolves.
- `secrets/<env>/hosts.sops.yaml` has not been renamed to `hosts.sops`.
- The current dev tree stores the k8s VM identities and addresses in `ansible/inventory/dev/group_vars/k8s_vms.sops.yaml` under `k8s_vm_definitions`; `k8s_vms` derives `k8s_vm_addresses`, `wywy_worker_ips`, and `wywy_control_plane_ips` from it. There is no `k8s-hosts.sops` or `proxmox-hosts.sops`, and the PVE aliases currently live in `hosts.sops`.
- `config/.env.network` still carries `{DEV_,}DATABASE_PROXMOX_HOST`, `{DEV_,}DATABASE_TEMPLATE_VMID` and the CI registry keys; the legacy scripts are the only readers.
- `scripts/lib/hosts.sh` keys on field 2 and does not require field 1 to be address-shaped, so it can neither resolve a field-3 alias nor reject a comment line whose field 2 happens to be the name. Nothing calls it with such input today.
