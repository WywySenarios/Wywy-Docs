## Architecture

4 containers: `sql_receptionist` (C11 HTTP API, port 2523), `create_tables` (Python 3.14 schema migration), `postgres` (PG18 + PostGIS), `cloudflared` (tunnel).

- **sql_receptionist**: raw HTTP server via pthreads, C11, libpq + libcyaml + jansson + libssl + libargon2. Routes: `/{db}/{table}/{data|tags|tag_names|tag_aliases|tag_groups|descriptors/:name}`. GET=SELECT (requires `ORDER_BY` + `LIMIT` in querystring, supports `id` and `parent_id` filters), POST=INSERT (validates against schema). All identifiers lower_snake_cased at runtime. Auth via `info.users` table, session cookie named `session`. Only admin gets past 501. Origin header must match `MAIN_URL` or `CACHE_URL`. OPTIONS → 204.
- **create_tables**: reads YAML → creates databases/tables/columns/tagging/descriptors. Installs PostGIS. Creates `info` DB with auth tables (users, sessions, api_keys).
- **postgres**: WAL backup via SSH to `$BACKUP_HOST`.
- **cloudflared**: tunnel from `/run/secrets/cloudflared_token`.

## Datatype validation

All in `apps/sql-receptionist/src/postgres/schema.c:169` (`validate_column`):
- `int`/`integer` → `json_is_integer`
- `float`/`number` → `json_is_real`
- `string`/`str`/`text` → `json_is_string`
- `bool`/`boolean` → `json_is_boolean`
- `date` → regex `[0-9]{1,4}-[0-9]{2}-[0-9]{2}`
- `time` → regex `xx:xx:xx` or `Txxxxxx` with optional fractional seconds
- `timestamp` → ISO8601-like `yyyy-mm-ddTHH:MM:SS`
- `enum` → validated as string (TODO: actual enum check)
- `geodetic point` → regex `POINT(x y)`, x∈[-180,180], y∈[-90,90]
- `pointer` → `json_is_integer` (FK to another table's `id` column)
- `polypointer` / `polymorphic pointer` → `json_is_integer` (polymorphic pointer ID)

Sub-columns for geodetic points: `_latlong_accuracy`, `_altitude`, `_altitude_accuracy` (all optional doubles).
Comments sub-column: `_comments` (optional string, only if `comments: true` in schema).
Polypointer sub-column: `_type` (optional string, target table name validated against `pg_tables`).

Toggle schema failure logging: `SQL_RECEPTIONIST_LOG_SCHEMA_FAILURES=TRUE`.

## Tests

C unit tests via valgrind (see [`containers/unit-test.mdx`](./master-database/containers/unit-test.mdx) for Docker details). Python integration tests expect running services. Set `SQL_RECEPTIONIST_LOG_REQUESTS=TRUE` / `SQL_RECEPTIONIST_LOG_RESPONSES=TRUE` to debug API traffic.

## Test portability

All tests (Python + C) must run to completion in both `test` and `prod` Docker Compose configurations. Never hardcode database names, table names, or config-specific assumptions. Instead, derive runtime values from `CONFIG` (loaded from `/config.yml`), use `to_lower_snake_case` for identifiers, and iterate over config entries rather than assuming a particular schema shape.

## Conventions

- All identifiers lower_snake_cased at runtime.
- **lower_snake_case rule**: Every column name, database name, and table name MUST be converted to lower_snake_case before being sent to PostgreSQL or encoded in an API response. Every incoming client request (URL path segments, querystring parameters) MUST be assumed to already be lower_snake_case — do NOT waste CPU on validation, just use the value as-is. Treat any missed conversion as a bug. Document all exceptions with inline comments.
- No linter, formatter, typechecker, or CI configured.
- Database separation must never be violated. Pointers/polypointers may only reference tables within the same database (exception: `sync_status` FK).
